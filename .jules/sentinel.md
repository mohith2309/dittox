## 2024-06-16 - Prevent SSRF in Cloud Functions HTTP Requests
**Vulnerability:** Server-Side Request Forgery (SSRF) was possible via webhook URLs containing private IP addresses, loopback addresses, or cloud metadata endpoints. By supplying a crafted URL, an attacker could force the server to execute arbitrary HTTP requests to internal resources.
**Learning:** We need to explicitly validate user-provided URLs against internal networks and specifically use Node's `URL` object parser to leverage built-in normalization, avoiding bypasses through URL obfuscation.
**Prevention:** Always parse URLs with the `URL` object to extract the hostname. Use strict regular expressions to validate that the hostname is not localhost, loopback (`[::1]`), private IPv4 networks (`10.x.x.x`, `192.168.x.x`, `172.16-31.x.x`), or cloud metadata endpoints (`169.254.x.x`). Additionally, enforce `redirect: 'error'` on `fetch` requests to prevent the initial safe URL from redirecting to a restricted internal endpoint.
