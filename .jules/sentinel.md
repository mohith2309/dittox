## 2024-06-25 - Fix Server-Side Request Forgery (SSRF) in Webhooks
**Vulnerability:** The application was vulnerable to Server-Side Request Forgery (SSRF) in the `sendWebhook` function in `functions/src/index.ts`. It fetched any URL provided by the user without validation.
**Learning:** Node.js native `URL` parsing is critical for SSRF protection to leverage built-in normalization and proactively prevent obfuscation bypasses (like hex/octal encoded IPs). Regex for URL validation must explicitly account for IPv6 addresses being wrapped in brackets (e.g., `[::1]`) and use strict anchors for IPv4 structures (e.g., `^(?:10\.\d...)$`) to prevent falsely flagging valid domains like `10.example.com`. Fetch options must also specify `redirect: 'error'` to avoid SSRF via redirection.
**Prevention:** Always validate webhook URLs using `URL` parsing, explicitly block localhost/private IP ranges with strict anchors and brackets for IPv6, and disable redirects on the fetch client.
