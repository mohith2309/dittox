## 2024-05-24 - [CRITICAL] Prevent SSRF in Webhook Outbox
**Vulnerability:** User-provided webhook URLs in Cloud Functions (`processWebhookOutbox` and `processNotificationIntent` email/sms webhooks) lacked Server-Side Request Forgery (SSRF) validation, potentially allowing attackers to scan internal networks, access cloud metadata endpoints, or exploit other internal services.
**Learning:** Native `URL` object parsing provides a robust foundation for SSRF protection because it inherently normalizes URLs, preventing common obfuscation techniques (like hex/octal encoded IPs) that string-based regexes might miss.
**Prevention:** Always validate user-provided URLs using `new URL()`. Explicitly block internal IPs (`localhost`, `127.0.0.1`, `169.254.169.254`, `metadata.google.internal`), enforce strict structural IPv4 matching to avoid falsely flagging valid domains like `10.example.com`, check for potential internal IPv6 formats, and configure the HTTP client (e.g., `fetch`) with `redirect: 'error'` to prevent bypasses via HTTP redirects.
