## 2025-02-25 - Fix Server-Side Request Forgery (SSRF) in webhooks
**Vulnerability:** The `sendWebhook` Cloud Function was blindly executing `fetch()` against any user-supplied URL without validation. This created a Critical SSRF vulnerability where an attacker could provide URLs pointing to internal networks (`10.x.x.x`), local services (`localhost`), or cloud metadata endpoints (`169.254.169.254`), allowing them to bypass firewalls and potentially access sensitive internal data or trigger unauthorized actions.
**Learning:** Cloud functions frequently act as proxies for user-initiated outbound requests. Trusting user-provided URLs in `fetch` without validating the host creates severe risk. Simple string matching is insufficient because attackers can obfuscate IPs (e.g., `0x7f000001` for `127.0.0.1` or `[::1]`).
**Prevention:** Always parse untrusted URLs using the native `URL` object (e.g., `new URL(url)`). This normalizes the URL and allows safe extraction of the `.hostname`. Then, strictly validate the hostname against a regex of prohibited private/internal IP blocks, explicit localhosts, and ensure `redirect: "error"` is set in `fetch` options to prevent HTTP redirect bypasses.
