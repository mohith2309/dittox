## 2024-06-10 - SSRF in Webhook Outbox
**Vulnerability:** A Server-Side Request Forgery (SSRF) vulnerability existed in `sendWebhook` because user-supplied webhook URLs (e.g. from `.webhookOutbox`) were fetched directly via Node's `fetch` API without any validation or sanitization.
**Learning:** This codebase dispatches arbitrary webhook URLs configured by the user. If we blindly fetch these URLs, an attacker can specify cloud metadata endpoints (e.g., `169.254.169.254`), `localhost`, or private VPC IP addresses to extract internal network details or query metadata tokens from the Firebase Cloud Functions environment.
**Prevention:** Always parse untrusted URLs using the `URL` object and validate the hostname against a blocklist of local/private IPs and names (`localhost`, `127.0.0.1`, `169.254.169.254`, `metadata.google.internal`). Additionally, configure the fetch client to drop HTTP redirects (`redirect: 'error'`) to prevent attackers from using an external redirection service to bypass the initial URL parsing checks.
