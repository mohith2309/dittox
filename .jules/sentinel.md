## 2024-07-08 - SSRF in Webhook Endpoints
**Vulnerability:** The Node.js application had a Server-Side Request Forgery (SSRF) vulnerability in its `sendWebhook` function where it blindly executed HTTP requests to user-provided URLs using `fetch()`. This could allow an attacker to send requests to internal infrastructure (e.g. `127.0.0.1`, `localhost`, `[::1]`) or access the sensitive Google Cloud Metadata server (`169.254.169.254`, `metadata.google.internal`). Additionally, standard `fetch` configurations follow 3xx redirects by default, which can be exploited by an attacker setting up an external server that responds with a 302 redirect pointing to an internal IP.
**Learning:** Preventing SSRF in Node.js requires validating the URL against a strict allowlist or blocklist *before* dispatching the request. Moreover, checking the URL host is not enough, you must disable following redirects (`redirect: "error"` or `"manual"`) to avoid bypass via HTTP 3xx redirect chains pointing to blocked internal hosts.
**Prevention:** Always parse untrusted URLs to inspect the hostname and port. Explicitly block internal IPs (`^127\.\d{1,3}\.\d{1,3}\.\d{1,3}$`), loopbacks (`localhost`, `[::1]`), and cloud metadata servers. Additionally, when using the fetch API, ensure `redirect: "error"` is passed in the options object to prevent redirect bypasses, even if it may break some webhook implementations that rely on redirects.
