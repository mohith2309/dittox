## 2025-02-06 - SSRF Vulnerability in Webhook Deliveries
**Vulnerability:** The application was making outbound HTTP requests (webhooks) using arbitrary user-provided URLs (`fetch` in Node.js) without validating the URL or preventing redirects, leading to a critical Server-Side Request Forgery (SSRF) risk where the application could be coerced into accessing internal networks, loopback interfaces, or cloud metadata endpoints.
**Learning:** Node.js `URL` parsing logic and standard fetch APIs can easily be used to access internal resources like `169.254.169.254` or `[::1]` if validation is not enforced, and `fetch` will by default follow redirects allowing attackers to bypass initial string-based URL filters.
**Prevention:** Always validate webhook URLs by parsing them with the `URL` API to strictly block `localhost`, `127.0.0.1`, `[::1]`, and match against private IPv4 structures (`10.x.x.x`, `172.16-31.x.x`, `192.168.x.x`, `169.254.x.x`). Additionally, when using `fetch` for outbound user-specified webhooks, explicitly set `redirect: 'error'` to prevent redirect-based SSRF bypasses.
