## 2024-07-02 - Prevent Server-Side Request Forgery (SSRF) in Outbound Webhooks
**Vulnerability:** The `sendWebhook` function directly passed a user-provided URL string to `fetch()` without any validation. This allowed Server-Side Request Forgery (SSRF), where an attacker could provide URLs targeting internal services (e.g. `localhost`, private IP ranges) or cloud instance metadata endpoints to extract sensitive data or pivot into the internal network.
**Learning:** Cloud Functions making outbound HTTP requests based on user-supplied URLs are extremely susceptible to SSRF. When implementing URL validation for SSRF protection in Node.js, native `URL` parsing is required, and IPv4 matches should use strict regexes (`^...$`) to avoid false positives (e.g., matching `127.example.com` when using `.startsWith('127.')`). Also, `redirect: 'error'` can break legitimate webhook endpoints, so validation alone without altering redirect behavior is preferred unless absolutely necessary.
**Prevention:** Always parse untrusted URLs using the native `URL` object and validate the `.hostname` against strict blocklists (localhost, `[::1]`, and private/metadata IP ranges using tight regexes).
