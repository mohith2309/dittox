## 2024-06-17 - SSRF Protection via Node URL Normalization
**Vulnerability:** The webhook dispatcher (`sendWebhook` in `functions/src/index.ts`) was fetching user-provided URLs without validation, opening up a Server-Side Request Forgery (SSRF) vector against internal Google Cloud/Firebase APIs or private network addresses.
**Learning:** Checking URLs with basic regex strings is insufficient because of obfuscation (e.g. integer IPs like `2886729738`, octal like `0177.0.0.1`). However, passing the URL into Node's `new URL(urlString)` automatically normalizes these representations to standard dotted-decimal or IPv6, making regex matching against `parsedUrl.hostname` safe and effective.
**Prevention:** Always use Node.js's native `URL` parsing to normalize URLs *before* performing checks against private IP ranges. Furthermore, enforce `redirect: "error"` on backend `fetch` calls to block attackers from bypassing initial validation via 301/302 redirects to internal networks.
